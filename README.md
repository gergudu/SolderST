# SolderST — Прошивка паяльной станции

## Платформа
- **MCU:** STM32F411CEU6 @ 96 МГц (HSE 25 МГц, PLL)
- **Плата:** кастомная PCB (2-канальная станция)

## Периферия
| Интерфейс | Назначение |
|-----------|-----------|
| SPI1 + DMA2 | Дисплей (ST7789 — рабочий; ILI9341 — драйвер в резерве под будущую замену дисплея, сейчас не подключён) |
| SPI2 | ADS1220 × 2 (RTD паяльника и отсоса) |
| I2C1 | EEPROM (конфиг) |
| TIM3 @ 200 Гц | ПИД + программный ШИМ нагревателей (оба канала) |
| TIM5 @ 100 Гц | Антидребезг кнопок, дебаунс записи в EEPROM |
| TIM2 @ 2 сек | Подавление DOCK датчика |
| TIM10 @ 30 сек | Таймеры сна (оба канала) |
| EXTI0 | DOCK датчик (вибрация, сброс сна паяльника) |

## Пины (из main.h)
| Пин | Имя | Назначение |
|-----|-----|-----------|
| PC13 | PWR_ON | Силовое питание нагревателей (push-pull, HIGH = включено) — управляется автоматически: включено, пока активен хотя бы один инструмент |
| PA3 | Disp_DC | Дисплей DC |
| PA4 | Disp_RST | Дисплей RST |
| PB4 | Solder_On | Нагреватель паяльника (активный высокий) |
| PB5 | Desolder_On | Нагреватель отсоса (активный высокий) |
| PB8 | ADS1220_Solder_CS | CS паяльника |
| PB9 | ADS1220_Desolder_CS | CS отсоса |
| PB12 | Btn_Pump | Кнопка насоса (активный низкий) |
| PB13 | Pump_On | Насос (активный высокий) |
| PB1 | Solder_Test | Контроль целостности паяльника |
| PB2 | Desolder_Test | Контроль целостности отсоса |

## Архитектура кода
```
Core/Src/
  main.c          — инициализация, основной цикл, прерывания
  config.c        — настройки, EEPROM, таймеры сна, CONFIG_ValidateAll
  state.c         — режимы, сервисное меню, Expert меню
  commands.c      — обработка событий кнопок, редактирование значений
  buttons.c       — FSM кнопок
  heater.c        — ПИД, ШИМ нагревателей, логика сна, RTD-диагностика
  ads1220.c       — драйвер двух ADS1220 (неблокирующее чтение)
  buzzer.c        — FSM активного зуммера, приоритеты сигналов
  ui.c            — отрисовка интерфейса
  display.c       — абстракция дисплея
  st7789.c        — драйвер ST7789 240×240
  ili9341.c       — драйвер ILI9341 320×240 (не используется, задел под будущую плату)
```

Общий для обоих каналов код (ПИД+ШИМ, автомат сна) вынесен в параметризованные
функции `Channel_Tick()`/`HEATER_OnSleepTick()` (heater.c) — паяльник и отсос
через тонкие обёртки `Channel_Tick_Solder/Desolder()`,
`HEATER_OnSleepTickSolder/Desolder()`, а не дублированием логики.

## Дисплей / UI
- Верхние 30px экрана — инфозона: индикатор записи в EEPROM (кружок, вспыхивает
  на ~0.3 сек в момент реальной отложенной записи, не всё время, пока есть
  несохранённые изменения), диагностика EEPROM (`Err EEPROM`, `hal=N`).
- Заголовки окон — шрифт 16px, под инфозоной.
- Пресеты SET1-3 — общая строка на всю ширину экрана (пресеты активного
  инструмента), не делится вертикальным разделителем между окнами
  паяльник/отсос. Вертикальный разделитель также не заходит в инфозону.
- Границы/шаг редактируемых величин сервисного меню (`min/max/step`) — общее
  поле `ServiceMenuItem_t`, единая точка правки для UI и логики (`GetEditContext()`
  в commands.c), без сравнения строк по лейблу.

## Логика сна (TIM10, тик = 30 сек)
Настройки таймеров (`PreSleep`, `Standby`) хранятся в EEPROM **напрямую в
минутах** (`TIMEOUT_MIN`/`TIMEOUT_MAX` = 1–30). Раннтайм-счётчик пересчитывается
из минут в 30-секундные тики только в момент старта отсчёта
(`CONFIG_MinutesToTicks()`), к самой настройке это не относится.

1. Старт отсчёта — счётчик взводится из `preSleepTimeout` (минуты → тики).
2. Счётчик дошёл до 0 (1й раз) → `preSleep = true`, T → `sleepTemp`, взвод 2й ступени.
3. Счётчик дошёл до 0 (2й раз) → канал выключен, нагреватель отключён.
4. Сброс паяльника — DOCK (EXTI0).
5. Сброс отсоса — BTN_VAC (передний фронт, `HEATER_PumpTick()` в главном цикле).

## ПИД (TIM3, 200 Гц) — оба канала, паяльник и отсос
- Пересчёт каждые 20 тиков (100 мс).
- Программный ШИМ, период 200 тиков (1 сек).
- Коэффициенты `Kp/Ki/Kd` — в Expert меню, хранятся в EEPROM, отдельно на канал.
- Контроль целостности нагревателя — в LOW фазе ШИМ (`*_TestPin()`).
- RTD-диагностика (`UpdateRtdFault`, `RtdFault_t`: обрыв датчика/нагревателя) —
  отдельно от целостности силовой цепи; при неисправности (`status.is_ok == false`)
  канал гарантированно не греет, ПИД сбрасывается (не копит интеграл).
- При старте канала ПИД и ШИМ полностью реализованы для **обоих** инструментов —
  паяльник и отсос идентичны по логике.

## EEPROM
- Инкрементальный dirty-flag механизм — пишется только то, что реально
  изменилось, по одному полю за проход (`CONFIG_SaveToEEPROM()`), с дебаунсом
  2 сек после последней правки (`SAVE_DELAY_TICKS`).
- `CONFIG_ValidateAll()` при загрузке клэмпит **все** поля конфига к их
  реальным диапазонам (presets/targets, PID, slope/bias, таймауты сна, flags) —
  защита от значений, оставшихся за пределами диапазона после смены констант
  в новой прошивке при валидном CRC16.
- Диагностика на шине: присутствие устройства + `hal=N` статус HAL-транзакции,
  показывается в инфозоне при ошибке.

## Известные ограничения
- **ADS1220: DRDY не разведён на отдельный пин** — шарится с DOUT,
  аппаратно не отделить в текущей ревизии платы. Чтение сделано
  неблокирующим через фиксированный период (`HAL_GetTick()`, ~55мс на
  канал, независимо на каждый), а не через настоящее событие DRDY —
  честная имитация, не идеал. Отдельный DRDY-пин планируется в
  следующей ревизии платы — тогда можно будет перейти на настоящий
  event-driven опрос (EXTI или poll DOUT между транзакциями).
- **ADS1220: регистры REG0/REG2 расходятся с документацией** — на
  реальном приборе паяльник даёт адекватную температуру, поэтому
  регистры не тронуты, но два момента открыты и не сверены со схемой:
  - MUX реально `AIN1(+)/AIN0(-)` (обратная полярность относительно
    комментария в `ads1220.h`) — эмпирически рабочая, но не
    подтверждена как намеренная.
  - Оба канала (паяльник/отсос) используют одинаковый `REG0_VAL`
    (общая `init_chip()`) — если RTD отсоса физически разведён на
    AIN2/AIN3 своего чипа (как было в старом комментарии), это может
    быть реальным несоответствием, а не только устаревшим текстом.
  - IDAC реально 1000мкА, не 500мкА как в старой документации — на
    расчёт температуры не влияет (рациометрическое измерение), но
    лишний самонагрев RTD.
- **ILI9341** — драйвер в дереве, но не зарегистрирован
  (`DISPLAY_RegisterDriver(&st7789_interface)` захардкожен в main.c) —
  задел под будущую замену дисплея, а не рабочий путь сейчас.
